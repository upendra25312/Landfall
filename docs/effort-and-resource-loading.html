Migration Effort & Resource Loading Model

A parametric effort model and month-by-month resource-loading plan for an Azure landing-zone build and server/application migration, sized from client-supplied inventory. Prepared by the pre-sales architecture team for RFP response.

Version 1.0/ Date 2026-09-06/ Basis reference estate, adjust to client/ Status DRAFT — architect & commercial review required

1 · How to use this

This is a parametric model: effort is driven by a small set of unit rates applied to counts from the client inventory (servers, applications, waves), plus fixed blocks for one-time work. Change the reference estate numbers in §3 to the client's actuals and every downstream table re-derives on the same logic.

Two things the pre-sales team owns and must confirm before this goes external:

  • Unit rates & complexity bands (§2) — calibrate against your last 2–3 comparable deliveries.
  • Blended day rates (§6) — from the current rate card / partner cost model, by delivery geography and on/offshore mix.
No discovery tooling. The client will not run Azure Migrate or install agents. This model therefore carries a heavier manual assessment block (§4.2) and a +15% inventory-quality contingency (§7). If the client later permits a short paid discovery, that contingency drops to +5% and replatform effort tightens.

Microsoft partner levers to net down the client price

  • Azure Migrate and Modernize (AMM) — partner-led funding for assessment & migration; typically covers a meaningful share of eligible delivery cost. Engage the Alliance team to submit the engagement early.
  • Azure Consumption Commitment (MACC) — if the client has one, this deal retires against it; use as a closing lever.
  • Cloud Accelerate Factory / FastTrack for Azure — Microsoft engineering assistance for landing-zone and first workloads at no cost; reduces the LZ build PD.
  • Azure Hybrid Benefit + Reserved Instances / Savings Plans — model in the run-rate to strengthen the TCO case vs on-prem.

7 · Assumptions & exclusions

Assumptions

  • Client provides timely access to owners, credentials, and change windows.
  • Inventory covers ≥ 90% of the estate; unknowns handled via contingency.
  • ExpressRoute circuit ordered by client in M1.
  • One target region + one DR region; single hub.
  • Non-prod migrated ahead of prod for each wave.
  • Client runs UAT; we support and trace defects.
  • No application code remediation beyond replatform config (refactor is out).

Exclusions

  • Application refactor / re-architecture (Refactor disposition).
  • Data centre exit, hardware disposal, contract termination.
  • Mainframe / midrange / appliance migration.
  • End-user compute, M365, identity greenfield.
  • Net-new security tooling licences.
  • Managed run service after hypercare (priced separately).
  • 24×7 cover outside cutover weekends.
